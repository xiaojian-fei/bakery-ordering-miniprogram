# 商家履约恢复

商家端接单、发货、标记待自取、完成核销和拒单退款会先保存原请求，再发送业务调用。页面重建后先读取当前环境、当前主体的恢复记录，展示待核对订单号，用户登录后点击“核对并重试原履约操作”继续原请求。

恢复记录只保存操作名称、订单ID、版本、请求ID及该操作所需的运单、核销码或拒单原因。员工密码和会话令牌只在既有认证流程中使用。恢复记录按运行时的环境命名空间和可信主体隔离。

存储失败阻止新的业务调用。结果未知时保留记录，重试沿用原参数和请求ID。已知业务拒绝会清除对应记录，要求重新核对。业务成功但记录清理失败时显示成功提示，并继续提供原请求核对入口。记录损坏时阻止新意图覆盖。

核销请求的原始核销码在结果待核对期间保存在本机恢复记录内，成功清理后删除。使用共享设备时应在离开前退出员工账号。

验证使用模拟微信缓存和真实应用服务执行页面入口，覆盖响应丢失后重建运行时、存储失败、损坏记录、清理失败及主体隔离。实际微信冷启动仍待验证。多设备或多个小程序实例共享存储的竞争协调仍待完善。
