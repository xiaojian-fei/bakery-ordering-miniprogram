TransactionRepository在图中是契约，不是仓库里额外虚构的实现类。当前适配为test/support/memory-repository.js，生产适配尚未实现。商品编辑不调用库存扣减；订单事务、退款事务和库存调整分别维护库存不变量。

```mermaid
sequenceDiagram
  actor Customer as 顾客
  participant Client as 公共客户端
  participant App as 应用入口
  participant Order as OrderService
  participant Tx as 事务适配器
  Customer->>Client: 选择商品、配送地址
  Client->>App: orders.quote
  App->>Order: 可信主体 + 业务参数
  Order->>Tx: 读取商品/本人地址/运费/库存
  Order-->>Customer: 展示整数分报价
  Customer->>Client: 确认提交
  Client->>App: orders.create(固定requestId及预期金额)
  App->>Order: 身份/会话验证后调用
  Order->>Tx: 请求去重、重新计价、检查并预留库存
  Order->>Tx: 同事务写订单、流水、事件、通知任务
  Tx-->>Order: 统一提交
  alt 客户端收到结果
    Order-->>Client: 返回订单
  else 响应丢失
    Client->>App: 用户确认后按原请求重试
    Order->>Tx: 命中原请求并读取原订单
    Order-->>Client: 返回同一张订单
  end
```

```mermaid
stateDiagram-v2
  [*] --> PENDING_PAYMENT: 下单并预留
  PENDING_PAYMENT --> PENDING_ACCEPTANCE: 模拟支付成功/扣实物库存
  PENDING_PAYMENT --> CANCELLED: 本人取消/释放预留
  PENDING_PAYMENT --> EXPIRED: 后台超时/释放预留
  PENDING_ACCEPTANCE --> ACCEPTED: 店员接单
  ACCEPTED --> SHIPPING: 配送登记
  ACCEPTED --> READY_FOR_PICKUP: 自取准备
  SHIPPING --> COMPLETED: 确认完成
  READY_FOR_PICKUP --> COMPLETED: 本人码核销
  PENDING_ACCEPTANCE --> CANCELLED: 店主拒单或批准售后退款
  ACCEPTED --> CANCELLED: 批准售后退款/不自动回库存
  READY_FOR_PICKUP --> CANCELLED: 批准售后退款/不自动回库存
```

模拟支付失败保留待支付状态；已配送/完成订单退款时保留物流主状态，仅paymentStatus改REFUNDED。售后批准后冻结后续履约，避免退款失败期间继续发货。售后拒绝后新申请生成新售后单，不让旧售后状态倒退。
