# 售后跨重启恢复

顾客售后申请、店主审核和整单模拟退款接入了持久化恢复。页面显示时只读取记录并展示待核对订单或售后ID，用户明确点击重试后提交原请求。申请原因、审核决定、说明、记录版本及请求ID保持原值。

申请、审核和退款与履约操作共用本地恢复引擎，分别使用独立的业务命名空间，继续按环境与可信主体隔离。保存记录成功后才发送写请求。已知业务失败清除原记录，未知结果保留，成功后清理失败会显示成功及待核对提示。损坏记录阻止新意图覆盖。

申请记录只保存订单ID、请求ID和申请原因。审核记录只保存售后ID、请求ID、版本、决定与说明。退款记录保存售后ID，服务端沿用每单唯一的退款记录来防止重复退款。密码与会话令牌由原有登录流程管理。

自动测试执行真实页面JS、公共客户端和应用服务，验证了申请响应丢失后重建页面、审核和退款跨页面恢复、原请求一致性、存储失败、损坏记录及清理失败。实际微信冷启动和多实例并发共享存储仍待验证。
