# 购物车配送与地址选择

日期：2026-10-28。本模块只推进配送方式与地址选择，不创建订单、不报价运费、不发起支付。

## 使用流程

新模式购物车默认自取。切到配送后，点击收货地址打开selectMode=true的地址列表；普通“查看收货地址”入口仍是管理模式，不向购物车回传。

点选地址时，列表先通过统一客户端重新读取指定的本人地址，并检查是否存在待确认的保存/删除操作。验证通过后，使用页面EventChannel回传addressSelected事件，内容仅为{addressId}，再返回购物车。没有来源通道时提示从购物车重新打开，不假装选择成功。

购物车隐藏期间只暂存ID，重新显示时再次读取服务器地址，显示白名单字段。事件正文中的联系人、电话、角色或整份地址快照不会直接用于展示。选择地址不更换用户的默认地址，也不自动采用默认地址。

## 失效与竞争处理

- 切回自取立即清空地址ID和展示；旧选择器事件不能在再次切回配送时恢复旧选择。
- 地址编辑后，购物车重新显示会读到当前内容；地址删除或无权访问时清空选择，不自动切换到另一条默认地址。
- 网络读取失败时隐藏旧展示，保留ID供重试核对；底层异常不显示给用户。
- 较旧的读取响应、重复选择事件、旧选择器事件，以及隐藏/卸载后返回的结果，不覆盖当前选择。
- 待确认的地址保存/删除需先处理，选择过程不调用保存或删除恢复；选择核对期间也不允许交叉发起删除。

这些检查不是最终下单授权。地址可能在本次预览之后再次变化，后续订单报价/创建仍必须由服务端重新核对归属、状态及快照。

新增10项测试，全量296项通过，详见[地址选择验收](tests/地址选择验收-20261028.md)。demo:miniapp通过实际App/Page注册入口及模拟EventChannel验证返回购物车显示，之后删除地址，再验证购物车清空选择。没有订单创建或支付调用。

配送方式和所选ID仅保留在当前购物车页面内存中，不承诺进程重启、跨设备或页面销毁恢复。miniapp-config默认仍为null；未启用生产传输或云环境。Node VM测试不包含WXML渲染、微信编译或真机验证，完整结算页仍待接入。
