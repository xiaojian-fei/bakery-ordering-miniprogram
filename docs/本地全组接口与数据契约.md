# 全组本地业务接口与数据契约

更新日期：2026-10-27。本文覆盖A/B/C新增的离线服务和演示工作台。原首页/详情/购物车/地址列表及新增编辑已提供可选客户端适配，默认配置仍为旧模式；不能把本地服务完成等同于微信端、云端或课程需求整体验收。

## 运行

```powershell
npm test
npm run demo:workflows
npm run preview:local
```

工作台地址：http://127.0.0.1:3218 。只监听本机，使用虚构商品/身份、随机测试口令、内存数据库和模拟支付。关闭进程后清空；端口占用时可设LOCAL_DEMO_PORT。没有安装依赖或软件，没有读取真实云数据，也不会联系真实群机器人。

工作台可以切换顾客、店员、店主。切换和测试口令自动填充只存在于scripts/local-demo-fixture.js，**不是生产登录方案，不得作为真实云函数/HTTP身份适配器发布**。生产仍需可信微信身份、真实员工口令及数据库权限。

addresses.list响应为{items,nextCursor,defaultAddressId}；defaultAddressId是本次查询事务中读取的本人默认指针，无选择时为null。客户端追加页时用它重算已显示地址的默认标记，避免保留前页旧标记。各页数据仍是各自查询时的快照，不承诺跨页数据库快照一致。

## 新增业务动作

所有动作仍使用`{action,data,staffToken?}`，客户端对应同名分组方法；异常、员工会话和结果未知处理沿用[客户端接口](客户端交易接口接入.md)。以下写操作均需8～80位requestId；版本冲突要刷新重新确认，不能自动覆盖。重复请求返回原操作结果快照，后续状态需再查询。

| action | 主要data | 权限 |
|---|---|---|
| catalog.list | category?,keyword?,includeUnavailable?,cursor?,limit? | 顾客看上架商品；含下架需店主 |
| catalog.get | productId,includeUnavailable? | 同上 |

| addresses.list | cursor?,limit? | 仅本人 |

| addresses.save | addressId,requestId,expectedVersion,name,phone,province,city,district,detail,makeDefault? | 仅本人 |
| addresses.remove | addressId,requestId,expectedVersion | 仅本人，软删除 |
| cart.get | 无 | 仅本人 |

| cart.clear | requestId,expectedVersion | 仅本人，旧版本不能清掉新修改 |
| orders.list | manage?,status?,cursor?,limit? | 本人；manage需店员/店主 |

新建商品/地址的expectedVersion为0；catalogVersion与inventoryVersion分离。商品编辑显式拒绝onHand/reserved/inventoryVersion，盘点继续调用inventory.adjust。新建商品实物库存为0，先盘点才能销售。产品只上下架，不硬删除历史订单所引用的商品。

地址只由users.defaultAddressId表示默认关系，不逐条存布尔默认标记。makeDefault未传表示保留选择；true选为默认；false仅在当前地址是默认时取消。删除默认地址清指针，订单保存的旧地址快照不变；软删除地址不能用于新订单。

购物车只估算当前商品小计，不预留库存、不固定价格、不计算最终运费。get返回items及issue、estimatedSubtotalCents、canCheckout。下架/缺货不擅自移除商品，但不可结算；下单仍重新读取价格、地址、配置及库存。

## 查询适配契约

在原transaction/get/set之外新增：

```js
const rows = await tx.query(collection, {
  filters: [{ field: 'ownerOpenid', op: 'eq', value: verifiedSubject }],
  orderBy: [{ field: 'createdAt', direction: 'desc' }, { field: '_id', direction: 'desc' }],
  after: null, // 或与orderBy字段对应的上页末项
  limit: 21
});
```

返回数组，每条带物理记录键对应的_id。limit为1～100；过滤支持eq/ne/gte/lt/lte/in/contains。contains为字面包含且不区分大小写，不能把用户输入直接作为正则表达式。查询排序必须稳定；after为排他二元/多元游标，不使用offset。过滤和排序均由业务服务构造，不能开放任意客户端查询。

公开分页为1～50条，返回{items,nextCursor}。游标绑定集合、筛选条件、排序和访问范围；它不是认证令牌，即使被修改，服务端仍应用角色与本人过滤。订单时间线按version排序，避免同毫秒事件出现v10排在v2之前。

统计按_id每批100条遍历，每集合最多10000条，超出明确返回REPORT_TOO_LARGE，不静默截断。MemoryRepository只是完整串行快照模型；真实数据库的查询事务范围、索引、冲突重试和聚合方案仍需实现并验证。

## 履约、售后及统计口径

物流为人工登记承运方/运单号，trackingMode=MANUAL，**没有连接快递物流API**。自取码在准备时随机生成并放入私有pickup_codes；订单列表和普通订单记录不含码。顾客仅能读取自己的待自取码，店员通过顾客出示的码完成核销；已用/退款后不能再次取码。

售后为REQUESTED→APPROVED→REFUNDED，或REQUESTED→REJECTED。拒绝后可用新请求再次申请新售后，一单不能并存两份处理中售后。批准与模拟退款分成可恢复的两步：批准后阻止继续履约和商家拒单；退款失败保留APPROVED，可调用原退款接口重试。退款与库存策略仍按最新订单状态决定，接单后不自动恢复烘焙品库存。

统计时间区间为[startAt,endAt)，最多31天，时间为毫秒。成交额按成功模拟支付发生时间；退款额按成功模拟退款发生时间（含商家拒单）；净额=成交额-退款额，跨期退款时允许为负。未支付、失败支付不算收入。

有效完成单数/商品销量按completedAt位于区间内、**当前仍为PAID+COMPLETED**的订单计算；整单退款后从有效销量排除。这是当前状态口径，之后退款会改变历史区间的有效销量，并不是冻结的历史财务快照。报告及界面明确显示模拟数据。

## 通知任务

订单和售后事件在同一业务事务内生成notification_outbox，业务回滚也回滚通知；事务中不发送外部消息。客户列表只显示事件、状态、时间和尝试次数，不返回租约令牌或通道异常。

NotificationJob需要显式注入send函数；本地演示只注入返回delivered:true的测试发送器。任务在事务中领取租约，事务外发送，再按租约令牌确认。默认租约30秒、最多5次、退避1/2/4/8秒…上限60秒；失败不回滚订单，过期租约可以重新领取，旧任务不能覆盖新租约结果。

这是**至少一次发送**：发送后数据库确认失败会再次使用同一eventId发送，真实通道需按eventId去重。没有声称外部消息恰好一次送达。真实发送器还需超时、凭据配置、授权通道、监控和部署触发，本轮均未接入。不要把本地测试通道“已处理”理解为真实顾客/商家已收到消息。

## 新增集合与保护

| 集合/字段 | 用途 |
|---|---|
| products.catalogVersion、catalog_events | 商品编辑冲突和审计，与库存版本分离 |
| carts的用户摘要键、version | 本人购物车、绝对改量与清空冲突 |
| addresses.deleted/version、users.defaultAddressId | 软删除与唯一默认地址 |
| pickup_codes | 私有一次性自取码，不直接允许客户端读写 |
| after_sale_links、after_sale_events | 单个活动售后链接与申请/审核/退款日志 |
| shop_config.shipping_rules、shop_events | 可版本化运费与店铺配置审计 |
| notification_outbox、notification_deliveries | 事务通知任务、租约及投递结果 |

集合名称是模型设计，不是已经在云端创建。角色、库存、订单、支付、售后、核销码、租约和配置写入仍需真实权限规则保护。索引围绕所有者+createdAt/_id、状态+createdAt、订单事件orderId+version、售后ownerOpenid/status+createdAt、财务createdAt、通知status+nextAttemptAt/leaseUntil规划，在实际数据库确认支持后再部署。
