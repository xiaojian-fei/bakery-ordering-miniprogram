# 网页端运行与验收

本项目已从小程序改为**浏览器访问的独立 Web 系统**：Node.js 单体服务 + SQLite 文件数据库 +
浏览器原生 ES 模块前端。运行时**不需要**微信开发者工具、微信账号、云开发或任何第三方 npm 依赖。

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **≥ 24** | 使用内置 `node:sqlite`，不需要安装数据库或驱动 |
| 浏览器 | 支持 ES 模块的现代浏览器 | Chrome / Edge / Firefox / Safari 近几年版本 |
| 依赖 | **零** | `package.json` 中没有 dependencies，无需 `npm install` |

## 二、启动

```bash
npm start                 # 等同于 node server/index.js
npm run dev               # 改代码自动重启（node --watch）
```

默认地址 `http://127.0.0.1:8080`。

首次启动会自动建库、建表、建索引，写入 6 个演示商品，并创建**首个店主账号**：

```
=== 首个店主账号已创建 ===
用户名：owner
初始口令：<随机生成，只在本次启动显示一次>
```

想自己指定口令（推荐，至少 12 位）：

```bash
# Linux / macOS
DB_FILE=data/bakery.sqlite OWNER_USERNAME=owner OWNER_PASSWORD='你的强口令123' npm start

# Windows PowerShell
$env:OWNER_PASSWORD='你的强口令123'; npm start
```

## 三、环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8080` | 监听端口 |
| `HOST` | `127.0.0.1` | 监听地址；对外提供服务时改 `0.0.0.0` 并务必开启 HTTPS |
| `DB_FILE` | `data/bakery.sqlite` | 数据库文件路径 |
| `UPLOAD_DIR` | `data/uploads` | 商品图片目录 |
| `OWNER_USERNAME` | `owner` | 首个店主用户名 |
| `OWNER_PASSWORD` | 随机生成 | 首个店主口令，**至少 12 位** |
| `SESSION_TTL_HOURS` | `12` | 网页会话有效期 |
| `MAX_BODY_KB` | `256` | 普通请求体上限 |
| `MAX_UPLOAD_KB` | `2048` | 图片上限 |
| `JOBS_INTERVAL_SECONDS` | `60` | 后台任务间隔，`0` 表示关闭 |
| `SECURE_COOKIES` | 关 | 置 `1` 时 Cookie 加 `Secure` 并启用 HSTS（HTTPS 部署时开启） |

## 四、账号与角色

| 角色 | 如何获得 | 能做什么 |
|---|---|---|
| 顾客 | 页面自助注册（用户名 + 至少 8 位口令） | 浏览商品、购物车、地址、下单、模拟支付、取消、申请售后 |
| 店员 | 店主在「店铺管理 → 员工账号」创建（口令至少 12 位） | 履约工作台：接单、发货、备货、自取核销 |
| 店主 | 首次启动初始化 | 以上全部 + 商品与库存、店铺运费、售后审核与退款、经营统计、员工账号 |

安全边界：顾客自助注册只能得到顾客身份；顾客与店员都无法通过任何接口进入店主功能，
服务端在 `core/domain/auth.js` 里做角色校验，浏览器端的按钮隐藏只是体验优化。

  checkout-*.js      结算草稿与失败恢复

## 六、HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 单页应用入口 |
| GET | `/api/client.js` | 由 `shared/` 现场生成的客户端 SDK 包 |
| GET | `/api/session` | 当前登录状态（含员工角色） |
| POST | `/api/register` | 顾客注册（自动登录） |
| POST | `/api/login` | 统一登录；员工/店主同时下发 HttpOnly 员工 Cookie |
| POST | `/api/logout` | 注销会话与员工令牌 |
| POST | `/api/action` | **业务动作统一入口**，34 个 action 见 `core/application.js` |
| POST | `/api/upload` | 店主上传商品图片（PNG/JPEG/WebP，≤2MB） |
| GET/POST | `/api/staff` | 店主查询 / 创建员工账号 |
| POST | `/api/staff/access` | 店主启用或停用员工 |
| POST | `/api/jobs/run` | 店主手动触发后台任务（演示用） |
| GET | `/uploads/<name>` | 商品图片访问 |
| GET | `/healthz` | 健康检查（数据库名、schema 版本、集合与索引数） |

业务动作的请求体固定为 `{ action, data }`，响应固定为 `{ success, data }` 或
`{ success:false, error:{ code, message } }`；这套契约与迁移前的客户端 SDK 完全一致。

## 七、安全设计

- **口令**：scrypt（N=32768, r=8, p=3）+ 16 字节随机盐，`timingSafeEqual` 比对；员工 12 位、顾客 8 位下限。
- **会话**：32 字节随机令牌放 `HttpOnly; SameSite=Strict` Cookie，数据库只存 sha256 摘要；
  注销立即失效，过期会话由后台任务清理。
- **员工令牌**：同样只在 HttpOnly Cookie 里，页面脚本拿不到令牌原文；前端只恢复"角色 + 到期时间"。
- **CSRF**：写操作必须是 `application/json` 且校验 `Origin`，跨站请求返回 403。
- **XSS**：前端不用 `innerHTML` 拼接数据，全部走 `textContent`；响应带 CSP `script-src 'self'`。
- **上传**：校验声明类型 + 魔数 + 大小，文件名服务端随机生成，访问路径白名单正则匹配。
- **越权**：所有动作在服务端按可信 `openid` + 员工会话判定角色，客户端参数不作为身份依据。
- **乐观锁与幂等**：写操作带 `expectedVersion` 与 `requestId`，重复提交不会重复下单/退款。

## 九、备份与恢复

SQLite 是单文件，备份即复制：

```bash
# 在线一致性备份（服务运行中也可执行）
node -e "const{openRepository}=require('./server/db');openRepository({dbFile:'data/bakery.sqlite'})
  .then(async r=>{await r.backup('data/backup-'+Date.now()+'.sqlite');r.close();})"

# 恢复：停服务 → 用备份覆盖 data/bakery.sqlite → 启动
```

上传图片在 `data/uploads/`，与数据库一起备份即可。`data/` 已在 `.gitignore` 中，不会误提交。
