# 业务核心接口（平台无关）

入口：`core/application.js` 的 `createApplication({ repository, resolveIdentity, clock, shipping })`。
它只接受一个 `repository`（`transaction` + `findExpiredOrders`）和一个**可信身份解析器**，
不依赖 HTTP、Cookie、数据库驱动或任何平台 API，因此浏览器、Node 测试与后台任务共用同一份业务逻辑。

## 一、请求与响应契约

```js
// 请求
{ action: 'orders.create', data: { /* 动作参数 */ }, staffToken?: '<64位十六进制>' }

// 响应
{ success: true, data: /* 结果 */ }
{ success: false, error: { code: 'OUT_OF_STOCK', message: '商品可售库存不足' } }
```

服务端只信任 `resolveIdentity(trustedTransportContext)` 解析出的 `openid`，
请求体里的 `openid`、`role`、`actor`、`system` 等字段一律忽略。
员工令牌必须由 `StaffAuthService` 校验，通过后 actor 才带 `staffVerified`。

## 二、动作清单（38 个）

| 分组 | 动作 | 说明 |
|---|---|---|
| 身份 | `identity.me` | 返回当前可信身份（openid + 角色） |
| 员工 | `staff.login` / `staff.logout` | 口令登录取得员工令牌 / 注销令牌 |
| 员工 | `staff.setPassword` / `staff.setAccess` | 店主设置员工口令 / 启用停用 |
| 商品 | `catalog.list` / `catalog.get` | 商品列表与详情（`includeUnavailable` 仅店主） |
| 商品 | `catalog.save` | 店主新增或编辑商品（不含库存字段） |
| 库存 | `inventory.adjust` | 店主调整实物库存，必须带原因 |
| 购物车 | `cart.get` / `cart.setLine` / `cart.clear` | 读取、按绝对数量写入、清空 |
| 地址 | `addresses.list` / `addresses.get` / `addresses.save` / `addresses.remove` | 收货地址 |
| 报价 | `orders.quote` | 只算钱不落库：商品小计 + 运费 + 总额 |
| 订单 | `orders.create` | 提交订单（预留库存，`requestId` 幂等） |
| 订单 | `orders.get` / `orders.list` / `orders.timeline` | 详情、分页列表（`manage` 为员工视角）、事件流水 |
| 订单 | `orders.pay` / `orders.cancel` | 模拟支付 / 顾客取消（均需 `expectedVersion`） |
| 订单 | `orders.pickupCode` | 自取核销码（仅待自取状态） |
| 订单 | `orders.reject` | 店主驳回并原子退款 |
| 履约 | `fulfillment.accept` / `ship` / `readyForPickup` / `complete` | 接单、发货、备货、完成（自取需核销码 12 位） |
| 售后 | `afterSales.apply` / `review` / `get` / `list` | 顾客申请、店主审核、查询 |
| 退款 | `refunds.executeApproved` | 按已批准的售后执行整单退款 |
| 店铺 | `shop.get` / `shop.save` | 店铺信息与运费规则 |
| 通知 | `notifications.list` | 通知 outbox 记录（员工视角） |
| 统计 | `statistics.summary` | 收款、退款、净额、销量（≤31 天区间） |

## 三、员工令牌与会话

- `staff.login` 返回 `{ token, role, expiresAt }`，令牌 64 位十六进制，数据库只存 `sha256` 摘要。
- 除 `staff.login`/`staff.logout` 外的员工动作需要 `staffToken`；网页端把它放在
  **HttpOnly Cookie**（`bakery_staff`）里，由 `server/http.js` 注入，页面脚本拿不到原文。
- 口令策略：员工 ≥12 位、顾客 ≥8 位，scrypt（N=32768, r=8, p=3）+ 16 字节随机盐；
  连续失败 5 次锁定 15 分钟；改口令或改权限会让旧会话失效。

## 四、错误码

| 类别 | 示例 |
|---|---|
| 身份 | `UNAUTHENTICATED`、`FORBIDDEN`、`AUTH_FAILED`、`AUTH_LOCKED`、`SESSION_CHANGED`、`ACCOUNT_DISABLED` |
| 请求 | `INVALID_REQUEST`、`INVALID_ITEMS`、`INVALID_QUANTITY`、`INVALID_DELIVERY`、`INVALID_ADDRESS`、`INVALID_CURSOR` |
| 并发 | `VERSION_CONFLICT`、`IDEMPOTENCY_CONFLICT`、`CART_WRITE_BUSY` |
| 业务 | `OUT_OF_STOCK`、`PRODUCT_UNAVAILABLE`、`PRODUCT_NOT_FOUND`、`PRICE_CHANGED`、`INVALID_STATE`、`ORDER_EXPIRED`、`INVALID_PICKUP_CODE`、`AFTER_SALE_EXISTS`、`ALREADY_REFUNDED` |
| 系统 | `INTERNAL_ERROR`、`REPORT_TOO_LARGE`、`INVALID_CONFIG` |

客户端把每个错误码映射成固定的中文提示与恢复建议（`shared/trade-errors.js`），
不向前端透出堆栈、SQL 或内部字段。

## 五、在 Node 里直接使用

```js
const { createApplication } = require('./core/application');
const { SqliteRepository } = require('./server/db/sqlite-repository');

const repository = new SqliteRepository({}, { file: ':memory:' });
const application = createApplication({
  repository,
  resolveIdentity: async context => ({ openid: context.openid })  // 只信任传输层解析结果
});

const result = await application.handle(
  { action: 'catalog.list', data: {} },
  { openid: 'owner' }
);
```

`scripts/demo-core.js`、`scripts/demo-client.js` 就是这种用法，可直接 `node scripts/demo-core.js` 跑。

## 六、后台任务

`core/jobs/` 下两个任务由 `server/index.js` 按 `JOBS_INTERVAL_SECONDS` 触发，也可以通过
店主接口 `POST /api/jobs/run` 手动执行：

- `order-expiry-job`：把超过支付时限的待支付订单关闭并释放预留库存（系统身份，不出现在动作路由里）；
- `notification-job`：从 `notification_outbox` 取件投递，带租约、重试与最大次数；
  网页端投递到本地 `data/notifications.log`，不连接任何外部通道。
