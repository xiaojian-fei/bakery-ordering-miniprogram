# 确认报价与待支付订单接入

2026-11-01。原购物车页面的新接口模式增加“确认报价并创建订单”，复用公共客户端、结算草稿恢复和微信缓存适配器。默认 `services/miniapp-config.js` 仍为空，新模式没有被自动开启。

## 操作流程

1. 点击“预览结算”取得只读报价，不创建订单。
2. 点击“确认报价并创建订单”。核对当前可信身份、购物车版本/数量及配送地址，重新获取报价；价格、费用、明细或地址变化时要求重新预览确认。
3. 新结算生成一次请求ID，先保存PREPARED记录，再保存SUBMITTING状态，成功后才发送创建请求。创建订单会由现有业务服务预留库存；本模块不支付、不清空购物车。
4. 成功显示订单号、金额和当前状态。结果未知时显示原订单金额，人工点击“核对并重试原订单”，始终使用原请求ID/商品/地址/预期总额，不按当前购物车重建请求。
5. 页面显示时读取草稿。PREPARED要求重新预览确认，SUBMITTING/UNCERTAIN要求人工重试，CONFIRMED只调用订单读取。页面显示本身不会自动创建订单。

已确认订单会持续保留并阻止第二次创建。本小模块止于一笔结算；结束本次结算、创建下一笔订单、支付、取消和订单列表入口留待后续模块。不得通过删除未知草稿绕过待确认操作。

## 实现

- `services/miniapp-checkout-submit.js`：确认、提交、恢复展示和显式重试；按生命周期阻止过期回调更新页面。
- `services/miniapp-cart-quote.js`：只在完整报价校验通过后保留私有选择快照，报价失效同步清除快照。提交前比较原始整数分及逐行价格，不通过格式化金额判断报价是否相同。
- `services/miniapp-runtime.js`：提供经验证的请求ID、可信主体绑定和单运行时共享的恢复管理器。存储仍由外部注入，不在运行时导入微信API。
- `services/wechat-checkout-storage.js` / `checkout-recovery.js`：复用既有协议，本轮未修改协议或扩大丢弃未知记录的权限。
- `pages/cart/cart.wxml`：确认按钮、原请求恢复、待支付订单及存储失败提示。

`createMiniappRuntime`新增可选`checkoutNamespace`，默认`bakery.checkout.v1`。正式接入时按AppID/云环境选择稳定、独立的命名空间；同一环境重启必须使用同一个命名空间。请继续为`requestId`注入真正唯一的生成器，不使用每次重启归零的计数器。

缓存只允许访问当前主体的一份结算记录，保存商品明细、金额、地址ID和请求ID等恢复必需字段，不保存收件人电话/详细地址、员工口令或令牌。缓存仍属于本地业务数据，不是加密保险箱。

## 验证与限制

新增17项专项，完整327项通过。见[本轮验收](tests/待支付订单验收-20261101.md)。本地演示在原有选址/报价/地址删除之后，切回自取、重新报价25.00元、人工确认创建待支付订单，并重建运行时只读找回同一订单。

缓存保存失败阻止发送新订单；创建成功但本地确认写入失败时显示成功及警告，保留SUBMITTING记录供原请求核对。身份变化清除页面原地址/报价/订单展示；返回隐藏中的页面可以恢复，解除忙碌状态。

验证使用Node VM、模拟微信缓存API与串行内存仓库，不等同于微信编译、WXML渲染、真机冷启动、生产事务或分布式并发验收。地址前后核对与订单创建不是同一事务；服务端创建时读取当前地址，尚未增加“按报价地址版本条件创建”的契约。跨运行时并行下单、跨标签页锁和草稿过期仍待完善。

本轮不部署云函数，不操作真实数据库、支付或商家通知，不覆盖工程配置已有的本地修改。
