# 部署与运维

面向单台服务器、单门店的部署方式。整个系统是一个 Node 进程加一个 SQLite 文件，
不需要数据库服务、消息队列或前端构建产物。

## 一、目录与文件

| 路径 | 内容 | 是否提交 |
|---|---|---|
| `core/ shared/ server/ web/` | 程序本体 | 是 |
| `data/bakery.sqlite` | 数据库（含 WAL 文件） | 否，`.gitignore` 已排除 |
| `data/uploads/` | 商品图片 | 否 |
| `data/notifications.log` | 通知投递记录（本地通道） | 否 |

## 二、生产启动

```bash
# 关键：通过环境变量指定强密码、监听地址与 HTTPS Cookie
HOST=0.0.0.0 \
PORT=8080 \
DB_FILE=/var/lib/bakery/bakery.sqlite \
UPLOAD_DIR=/var/lib/bakery/uploads \
OWNER_USERNAME=owner \
OWNER_PASSWORD='至少12位的强密码' \
SECURE_COOKIES=1 \
node server/index.js
```

首次启动会建库建表、写入演示商品并创建店主账号。**把初始化打印的密码立即改掉或事先用
`OWNER_PASSWORD` 指定**；不要再使用演示密码。

### systemd 单元示例

```ini
# /etc/systemd/system/bakery.service
[Unit]
Description=Bakery web service
After=network.target

[Service]
Type=simple
User=bakery
WorkingDirectory=/opt/bakery
Environment=HOST=127.0.0.1
Environment=PORT=8080
Environment=DB_FILE=/var/lib/bakery/bakery.sqlite
Environment=UPLOAD_DIR=/var/lib/bakery/uploads
Environment=SECURE_COOKIES=1
Environment=OWNER_USERNAME=owner
# 密码放在 EnvironmentFile 里并限制权限 600，不要写进单元文件
EnvironmentFile=/etc/bakery.env
ExecStart=/usr/bin/node server/index.js
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd -r -s /usr/sbin/nologin bakery
sudo install -d -o bakery -g bakery /var/lib/bakery /var/lib/bakery/uploads
sudo chmod 600 /etc/bakery.env
sudo systemctl enable --now bakery
```

进程收到 `SIGINT`/`SIGTERM` 会关闭 HTTP 服务、停止后台任务并关闭数据库，数据先落盘再退出。
不要在运行中直接 `kill -9`，虽然 WAL 能保住已提交事务，但会留下 WAL 文件待下次启动恢复。

## 三、HTTPS 反向代理

`SECURE_COOKIES=1` 会给会话 Cookie 加 `Secure` 并启用 HSTS，此时**必须**通过 HTTPS 访问，
否则浏览器不会回传 Cookie。Nginx 样例：

```nginx
server {
    listen 443 ssl http2;
    server_name bakery.example.com;

    ssl_certificate     /etc/letsencrypt/live/bakery.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/bakery.example.com/privkey.pem;

    client_max_body_size 3m;   # 商品图片上限 2MB，留出 base64 余量

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 20s;
    }
}

server {
    listen 80;
    server_name bakery.example.com;
    return 301 https://$host$request_uri;
}
```

注意事项：

- 应用本身校验请求的 `Origin` 是否与 `Host` 一致，反代必须**原样转发 `Host`**，否则写操作会被 403 拒绝。
- 应用按对端 IP 做注册/登录限流；若前面还有一层代理，需要保证 `X-Forwarded-For` 可信或启用真实 IP 模块。
- 上传的图片走应用自身的 `/uploads/`，不需要额外静态站点配置。

## 四、备份与恢复

数据库是单文件，备份即复制；SQLite 支持在线一致性备份：

```bash
# 在线备份（服务运行中也可以）
node -e "const{openRepository}=require('./server/db');openRepository({dbFile:'/var/lib/bakery/bakery.sqlite'})
  .then(async r=>{await r.backup('/var/backups/bakery-'+Date.now()+'.sqlite');r.close();})"

# 连同图片一起打包
tar czf /var/backups/bakery-assets-$(date +%F).tar.gz -C /var/lib/bakery uploads
```

恢复：

```bash
sudo systemctl stop bakery
cp /var/backups/bakery-<时间戳>.sqlite /var/lib/bakery/bakery.sqlite
rm -f /var/lib/bakery/bakery.sqlite-wal /var/lib/bakery/bakery.sqlite-shm
sudo chown bakery:bakery /var/lib/bakery/bakery.sqlite
sudo systemctl start bakery
curl -s http://127.0.0.1:8080/healthz
```

`/healthz` 返回数据库名、schema 版本、集合数与索引数，可用于启动后自检。

## 五、运行检查

| 检查项 | 方式 |
|---|---|
| 进程与端口 | `systemctl status bakery`、`ss -ltnp \| grep 8080` |
| 健康检查 | `curl -s http://127.0.0.1:8080/healthz` |
| 数据是否在增长 | `ls -l /var/lib/bakery/`，WAL 文件大小 |
| 通知是否投递 | `tail -f /var/lib/bakery/notifications.log` |
| 后台任务是否执行 | 启动日志中的"后台任务：超时关闭 N 单" |
| 会话是否过期 | 默认 12 小时，过期后页面提示重新登录 |

日志没有做结构化落盘，直接进 systemd journal（`journalctl -u bakery -f`）。应用**不会**记录
密码、令牌或图片内容；失败原因会以业务错误码出现在响应里，方便前端提示。

## 六、升级

1. 停服务、做一次备份（见上）。
2. 拉取新代码；`package.json` 没有第三方依赖，不需要 `npm install`。
3. 启动服务。建表语句是幂等的（`CREATE TABLE IF NOT EXISTS`），索引同理；
   schema 版本记在 SQLite 的 `PRAGMA user_version` 上，若库版本高于代码版本会拒绝启动
   （`DATABASE_SCHEMA_TOO_NEW`），避免旧代码写坏新结构。
4. 跑一次 `node scripts/smoke-web.js verify` 确认历史数据仍可读。

## 七、容量与性能参考

在当前开发机（Node 24.21、SQLite 3.46.1）实测：

| 场景 | 结果 |
|---|---|
| 50 个顾客同时抢 10 件库存 | 恰好 10 单成功，40 单 `OUT_OF_STOCK`，零超卖 |
| 50 个并发下单请求 | 63 ms，约 794 请求/秒 |
| 500 个并发查询 | p50 7.2 ms / p95 11.4 ms / max 13.8 ms，约 1990 请求/秒 |

这是单进程 + 单文件的成绩，适合单门店课程项目与小型店铺。若要支撑更大并发，优先考虑：
把写事务改为批量提交、给热查询补索引、把只读查询放到 WAL 快照上。

## 八、安全清单（上线前逐条确认）

- [ ] `OWNER_PASSWORD` 是 12 位以上强密码，且没有出现在代码或仓库里
- [ ] 服务以非 root 账号运行，`data/` 目录属主正确、权限不含 other
- [ ] `SECURE_COOKIES=1` 且全站 HTTPS，HTTP 自动跳转
- [ ] 反向代理原样转发 `Host`，写操作不会被误判为跨站
- [ ] 备份任务已配置，且演练过一次恢复
- [ ] 通知通道确认是本地落盘（不期望真实外发时）
