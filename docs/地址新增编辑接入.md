# 地址新增与编辑接入

日期：2026-10-27。本模块将原pages/add-address页面接入统一客户端，配合地址列表完成新增、读取、编辑和默认地址设置。删除与结算选址未接入。

## 页面行为

从地址列表新增，页面生成本次地址ID；编辑时通过addresses.get直接读取指定的本人地址，不扫描分页列表。保存提交地址ID、服务器版本、联系人/电话/省市区/详情、requestId及可选makeDefault，不提交openid、角色或其他授权标记。

姓名等字段先校验必填和长度并去除首尾空白。服务器继续校验归属、版本和内容。连续点击只保存一次，成功后禁用再次提交，由用户返回地址列表查看。

默认开关未修改时不传makeDefault，保留服务器当前选择；主动切换才传true/false。这样，另一个页面在编辑期间更换默认地址后，旧表单仅改内容不会把默认地址切回去。服务端仍用users.defaultAddressId唯一指针，在事务中更新。

遇到VERSION_CONFLICT、地址删除或无权编辑时，保存入口保持禁用。重新加载按钮明确提示会覆盖表单，用户确认点击后读取最新服务器版本，再重新修改。身份失效或主体变化时清空表单个人信息，不继续保存。

## 结果未知和恢复

services/miniapp-address-editor.js在发送前冻结白名单原请求；网络断开或成功响应畸形时保留该请求，锁定表单，重试使用相同requestId、地址ID、版本及内容。新的保存意图不能覆盖待确认请求。

离开页面后，列表显示“继续上次地址保存”。进入表单、明确恢复后可重试原保存。保存恢复记录只在同一运行时内存中，不写磁盘或微信缓存，不保存口令/令牌。进程关闭后不保证恢复；重新进入须先核对地址列表，不自动再次新增。

重复请求返回原操作结果快照。即使在原响应丢失后，其他页面又编辑了该地址，重试也不会覆盖后续版本；返回列表时再读取最新数据。不能把原请求的成功快照当成地址当前版本。

## 接口与配置

- 新增addresses.get，data仅含addressId，只允许读取本人未删除地址；返回既有地址DTO，含version/isDefault，排除ownerOpenid、创建时间等内部字段。
- 客户端提供client.addresses.get(addressId)。页面运行时的addressEditor负责身份核对、白名单保存、并发阻挡及未知结果重试。
- 原*.legacy.js保留。miniapp-config仍默认导出null，未自动启用新模式；真实可信send和唯一ID生成器仍由选定平台接入。
