# 初始店主与旧数据迁移准备

更新日期：2026-10-23。负责人A。当前提供可本地验证的初始化模块与迁移预检工具，未连接、读取或修改原云数据库；没有实际执行导入或生产账号初始化。

## 适用范围

只为**全新测试环境**准备数据。旧商品价格、地址模型与交易核心字段不同；旧项目的库存、支付和权限信息不能据页面状态自动推断。原数据库保留备份，旧订单保持原导出归档，不能把它们转换成新系统的成功收款或库存流水。

工具只准备products、addresses及默认地址映射userDefaults，不迁移员工角色、口令、会话、支付、退款、订单状态或机器人凭据。真实导入器、字段写入规则、索引、安全规则、维护窗口和回滚步骤仍待目标数据库确定后实现。

## 旧数据输入与库存盘点

原始导出保存在项目.local目录，已被.gitignore忽略；报告含地址和账号标识，也只保存在该目录。不要用真实导出覆盖仓库中的测试夹具。

示例仅用虚构数据：

```json
{
  "products": [
    { "_id": "bread", "name": "测试司康", "price": 11.9, "isOnSale": true }
  ],
  "addresses": [],
  "orders": []
}
```

单独准备库存盘点JSON，以商品ID映射实际计划放入测试环境的实物库存：

```json
{ "bread": 12 }
```

不能用monthSales代替onHand，不能猜测缺失库存。工具要求每条商品都有明确的非负整数库存，并设reserved=0、inventoryVersion=0；若旧记录已有非零reserved则阻断，需先核对活动交易。

## 执行预检

在开发版根目录执行：

```powershell
npm run prepare:legacy -- --input .local/legacy-export.json --stock .local/stock-counts.json --out migration-plan.json
```

两个输入文件需由有权限的开发者预先准备。命令只读取本地JSON，不登录云环境，不安装依赖。每个输入文件上限20MiB；结果写到.local/migration-plan.json，已有同名结果不会覆盖，可换新文件名重跑。

控制台仅显示数量与状态，不输出顾客字段或原始JSON错误片段。退出码0表示预检无阻断，2表示生成了含阻断项的报告，1表示输入/本地文件操作失败。

结果包含sourceSha256、stockSha256、schemaVersion、sourceCounts、blockers、warnings、ready和prepared。摘要用于核对准备结果对应哪份输入，不代表备份或数据已导入。ready仅表示本工具检查通过；仍需人工检查全部warnings、目标环境权限与业务规则。

ready=false时prepared可能含通过单条检查的候选记录，**不得挑选后直接导入**。先解决全部阻断项并重新生成整份结果。

## 转换规则

| 数据 | 处理 |
|---|---|
| price（元） | 以十进制文本精确转整数priceCents；最多两位小数，不自动四舍五入 |
| 已有priceCents | 必须为正安全整数；若同时有price，二者必须一致 |
| 商品ID/地址ID | 保留合法ID，重复或非法ID阻断 |
| 上下架 | 显式true才上架；缺失则下架并提醒，非布尔值阻断 |
| 商品其他信息 | 只保留名称、描述、类别、图片、招牌标记等白名单字段 |
| 旧云图片 | 只保留原fileID并提示核对访问权限，不复制文件或承诺可访问 |
| 地址归属 | ownerOpenid/openid/_openid统一为ownerOpenid，多个来源矛盾则阻断 |
| 默认地址 | 生成userDefaults中的openid/defaultAddressId映射；多个默认地址阻断，不自动挑选 |
| 用户角色/口令 | 不从旧数据生成、提升或覆盖权限 |
| 历史订单 | 只计入排除数量并提醒归档，不创建新orders/payments/refunds |

userDefaults是供未来导入器使用的字段补丁，不是可直接替换users集合的完整记录。应用时需验证地址归属，并保留既有角色、授权版本、会话和其他受保护字段。默认地址管理的日常业务服务仍由B负责。

## 首个店主初始化

模块为cloudfunctions/api/setup/owner-bootstrap.js，只供可信部署代码调用，未注册任何application客户端动作：

```js
const { OwnerBootstrap } = require('./cloudfunctions/api/setup/owner-bootstrap');
const bootstrap = new OwnerBootstrap(realTransactionalRepository);
// verifiedOwnerId及initialPassword由部署管理员在可信环境中提供。
const result = await bootstrap.initialize({
  ownerOpenid: verifiedOwnerId,
  password: initialPassword
});
```

首次初始化在同一事务写users、staff_credentials、system_settings[first-owner-v1]和auth_events。口令使用既有随机盐scrypt方案，返回值仅为initialized/changed；没有默认部署账号或口令，不返回哈希或原始口令。

同一店主重复执行返回changed:false，**即使传入新口令也不会重设旧口令**；改口令应走受保护的既有管理流程。目标已有账号/残留口令、初始化标记指向其他店主或标记与账号不一致时拒绝覆盖，需要部署管理员核对。

该初始化协议依赖“全新环境、角色集合受保护、仅此可信初始化流程创建首个店主”的前提，不扫描全库查找其他既有店主，也不接管旧环境；不能把它当作已上线系统的账号恢复接口。真实初始化前必须由管理员确认这些前提。将该模块暴露为公开HTTP/云函数动作会破坏前提，因此客户端白名单没有初始化入口。

生产事务适配器需确保标记、账号、口令和事件一起提交，并在冲突时重试或拒绝；本地并发用例只能证明内存事务模型下的规则。真实密码输入/密钥保管、执行权限与首个微信身份确认仍需部署侧接入，勿把口令放进命令行参数、仓库、日志或聊天。
