## 供队友对接的约定（草案）

下面展示领域业务方法；统一action路由和响应包已在application工厂实现，但尚不是可通过wx.cloud.callFunction调用的线上API。调用格式与权限见[平台无关交易核心接口](平台无关交易核心接口.md)。

### 创建订单

```js
const order = await service.create(trustedActor, {
  requestId: 'checkout-unique-001',
  items: [{ productId: 'berry', quantity: 2 }],
  deliveryType: 'delivery', // 或 pickup
  addressId: 'address-a',  // 配送必填，自取忽略
  expectedTotalCents: 3380, // 可选；报价变化则返回 PRICE_CHANGED
  remark: '演示备注'
});
```

- 用户/角色必须由服务端读取微信上下文、用户记录和员工会话后构造，不能接受 event.actor、event.role 或客户端 openid 作为可信身份。
- 顾客身份形如 `{ openid, role: 'customer' }`；员工还需要已验证的 `staffVerified: true`，系统任务需要独立验证的 `trustedSystem: true`。这些标记只是模块边界约定，不是认证实现，也不是让客户端传 true 获得权限。
- requestId 对每次新的结算唯一；网络失败重试沿用旧 requestId 和相同业务参数。更改购买内容需要新 requestId。已取消的请求再次重试会返回原订单，不会自动重建。
- 最多20行输入，同一商品合并后最多99件；数量必须是整数。价格只读取服务器商品记录的 priceCents，不采用客户端 price、totalPrice 或 shippingFee。
- 示例 3380 分来自商品 1190×2 加北方运费1000，不是固定业务价格。
- 产品字段：`_id, name, priceCents, isOnSale, onHand, reserved`；本地测试要求上架状态显式为 true。
- 地址字段：`_id, ownerOpenid, name, phone, province, city, district, detail`；仅本人地址可用，订单只保存需要的字段快照。
- 结果包含 `_id, ownerOpenid, items, amounts, status, paymentStatus, expiresAt, version`；所有金额是整数分，时间是毫秒时间戳，页面自行格式化。

旧数据使用 price（元）、openid 等字段，与本轮约定不完全相同。未来需要明确的数据迁移/映射脚本，不可直接把旧数据复制到新模型后假定可用。

### 订单操作

```js
await service.simulatePay(trustedActor, orderId, { expectedVersion: 1 });
await service.cancel(trustedActor, orderId, { expectedVersion: 1 });
await service.expire(trustedSystemActor, orderId);
```

simulatePay 不调用真实支付，默认模拟成功。模拟失败使用明确的 outcome 和用于重试去重的 attemptId：

```js
await service.simulatePay(trustedActor, orderId, {
  outcome: 'failure', attemptId: 'payment-attempt-001', reasonCode: 'DECLINED'
});
```

支持 DECLINED、NETWORK_ERROR、USER_CANCELLED；失败保持待支付和原预留库存，在 payment_attempts 中记录失败并增加订单版本。重复尝试不会重复写日志；失败后可用最新版本重新成功支付。同一 attemptId 不可更换订单或失败原因。使用 success:false 会明确拒绝，避免误认为模拟成功。

### 整单模拟退款（A提供给C）

```js
const { RefundService } = require('../cloudfunctions/api/domain/refund-service');
const refunds = new RefundService(repository);
await refunds.refundApproved(trustedOwnerActor, afterSaleId, { expectedOrderVersion: 2 });
```

仅经过验证的店主可调用。C的审核服务必须先生成受保护的 after_sales 记录，包含 `_id, orderId, ownerOpenid, status: 'APPROVED', approvedBy, approvedAt, reason`；approvedAt 为毫秒时间戳，reason 为1～200字。客户端不能自行写APPROVED或传角色获得权限。该方法不替代售后申请、审核与拒绝流程。

退款金额取原订单及成功模拟支付记录，整单金额（含原运费）一次性退回，不采用客户端或售后记录随意传入的金额。不支持部分退款。相同售后重复调用返回同一退款；另一售后不能让同一订单再次退款。退款、订单、售后、库存与事件通过同一个事务提交，失败全部回滚。

烘焙库存策略v1：**仅待接单订单退款时自动恢复实物库存**；接单后视为开始备货，待自取、配送中及完成的订单均不自动恢复。尚未履约的退款订单转已取消，配送中/完成订单保留物流主状态，paymentStatus转REFUNDED。这个策略需要团队确认，后续如调整必须同时修改规则和测试。

原 payments 成功记录保留用于成交额，refunds 记录用于退款额，净额=成功收款-成功退款。不要仅因原收款记录仍为SUCCEEDED就把已退款订单计为净收入。失败尝试 payment_attempts 不计成交额。

支付/取消只能由本人执行。支付截止时刻 `now >= expiresAt` 拒绝付款；释放由 expire 操作执行，**本地没有启动定时器，云端还需要部署定时扫描**。超时扫描遇到已处理订单不再次释放。

状态枚举采用英文稳定值，界面映射为中文：

| 值 | 显示 |
|---|---|
| PENDING_PAYMENT | 待支付 |
| PENDING_ACCEPTANCE | 待接单 |
| ACCEPTED | 已接单 |
| SHIPPING | 配送中 |
| READY_FOR_PICKUP | 待自取 |
| COMPLETED | 已完成 |
| CANCELLED | 已取消 |
| EXPIRED | 已超时 |

履约负责人 C 可使用 nextStatus 校验接单、发货、自取和完成的状态规则，但还需要自己实现物流/核销参数校验、持久化、授权入口及页面。不要直接在客户端调用规则后写数据库。

主要错误码：UNAUTHENTICATED、FORBIDDEN、INVALID_ITEMS、INVALID_QUANTITY、PRODUCT_NOT_FOUND、PRODUCT_UNAVAILABLE、OUT_OF_STOCK、PRICE_CHANGED、IDEMPOTENCY_CONFLICT、INVALID_STATE、ORDER_EXPIRED、VERSION_CONFLICT。前端按错误码给出重新确认、刷新或改量等操作。

## 云数据库适配契约

未来生产 repository 必须实现：

```js
repository.transaction(async tx => {
  const record = await tx.get(collectionName, id); // 不存在返回 null
  await tx.set(collectionName, id, record);        // 完整记录写入
  return result;
});
```

必须保证回调中的读写是同一个真实事务，成功后统一提交，抛错则全部回滚；根据实际 SDK 限制实现冲突处理/重试，重试回调里不得发送通知。提交结果不明时也必须能按原请求重试，不能只靠单进程 Promise 队列。

业务使用 products、addresses、orders、request_keys、payments、payment_attempts、refunds、after_sales、order_events、inventory_movements。云适配层负责 _id 的读写规则、字段类型、集合初始化以及权限/索引；尤其检查原子请求去重和库存争用。也可以改为独立HTTP后端与数据库repository，领域规则不需依赖微信SDK。

MemoryRepository 为测试专用：隔离副本 + 全局串行队列，故意提供理想的原子语义。它能检查规则和回滚后的结果，**不能证明真实云事务、分布式锁、并发吞吐或超卖问题已经解决**。
