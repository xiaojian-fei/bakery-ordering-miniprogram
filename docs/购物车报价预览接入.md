# 购物车报价预览接入

2026-10-31。基于现有配送选址，在原购物车页面的新接口模式中增加“预览结算”。默认 `services/miniapp-config.js` 仍为 `null`，直接导入开发者工具时仍运行旧模式；本地演示通过注入公共客户端运行新模式。

## 行为

- 展示逐行商品单价/数量/小计、商品金额、运费、合计及自取/配送信息。金额展示来自 `orders.quote`，不将购物车估算直接当作结算价。
- 报价前读取当前可信身份和购物车。若版本或商品数量与页面不同，刷新购物车并要求再次报价，不直接替用户确认另一组数量。
- 配送必须先选址并成功核对；报价前后重新读取本人地址。地址版本或内容变化时更新地址、清除金额并要求再次报价，删除/越权/身份失效时清除原地址。
- 报价服务已有的事务逻辑重新读取商品现价、可售库存和运费配置。自取运费为零，配送使用服务端包邮门槛和地区规则。
- 数量修改、恢复购物车写入、配送方式切换、重新选址/核对、刷新及离开页面均使旧报价失效。请求代次和输入快照阻止旧响应覆盖新状态；重复点击不重复请求。
- 购物车修改结果未知时先恢复原操作；配送地址保存/删除结果未知时先恢复地址操作。只读报价失败可点击“重新报价”，原始传输异常不会显示。
- 校验响应金额为非负整数分、行数量和商品匹配、逐行及总额相加一致。页面展示字段采用白名单，不透传接口内部字段。

## 代码与验证

- `services/miniapp-cart-quote.js`：报价预览控制器、响应校验和过期响应保护。
- `services/miniapp-pages.js`、`services/miniapp-address-selection.js`：购物车入口、生命周期和选址失效钩子。
- `pages/cart/cart.wxml` / `cart.wxss`：报价明细、重新报价和刷新入口；原旧模式保留。
- `test/miniapp-cart-quote.test.js`：14项专项用例，经真实App/Page入口、公共客户端和内存应用服务执行。
- `npm run demo:miniapp`：虚构配送地址下，商品25.00元＋运费13.00元＝合计38.00元；删除地址并返回后清除预览。

本轮没有新增依赖，没有调用 `orders.create` 或支付接口，没有生成结算请求ID、预留库存或保存报价缓存。报价仅是本次读取的预览，不保证后续价格/库存不变；购物车、地址和报价的跨接口读取也不属于单个生产数据库事务。将来创建订单仍必须重新校验，并接入已有请求去重及结算草稿恢复。

Node VM验证执行真实JS入口但不渲染WXML，不等同于微信编译、真机或云端验收。生产传输、云数据库适配、下单/模拟支付页面、真实冷启动仍待完成。
