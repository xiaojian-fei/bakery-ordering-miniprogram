# 面包脑袋爱包包商品订购小程序

以下描述导入时保留的原微信页面基线；新增离线服务和浏览器工作台的进度以上方链接为准。

面向单家烘焙店的原生微信小程序，提供商品浏览、购物车、收货地址、配送或自取、订单提交和后台管理。订单创建后可查看收款码并提交付款确认，由商家人工处理订单。

本 README 根据“小程序基础功能版最新版备份”的源码整理。当前备份包含基础业务代码，不包含云数据库数据、云存储文件和控制台权限配置。完整运行需要微信开发者工具及可访问的小程序云环境；目前尚未完成开发者工具编译和真机验收。

## 功能

| 使用方 | 已有功能 |
|---|---|
| 顾客 | 按分类浏览商品、查看详情、加入购物车、修改数量、管理收货地址 |
| 顾客 | 选择自取或配送、计算运费、填写备注、提交订单、查看和取消待支付订单 |
| 顾客 | 查看收款码、继续付款、提交“已付款”确认 |
| 后台 | 查看和筛选订单、人工确认订单、将订单标记为完成 |
| 后台 | 新增和编辑商品、上下架、删除商品、上传图片、设置招牌商品 |
| 后台 | 编辑店铺信息、轮播图、收款码，查看简单订单统计 |
| 云函数 | 获取微信身份、读取商品、创建订单、获取订单列表、尝试发送企业微信机器人提醒 |

当前实现使用顾客与后台管理入口，尚未实现独立的顾客、店员、店主三角色授权。库存、售后、退款及物流跟踪不在本备份的功能范围内。

## 技术栈

| 部分 | 技术 |
|---|---|
| 页面逻辑 | JavaScript、微信小程序 API |
| 页面结构 | WXML |
| 样式 | WXSS |
| 后端 | JavaScript 云函数、`wx-server-sdk` |
| 数据 | 微信云开发文档型数据库 |
| 图片 | 微信云存储 |
| 订单提醒 | Node.js `https` 模块调用企业微信机器人 webhook |

该项目没有 Python、Java 或独立 Web 服务端。可以用 Codex、VS Code 等编辑源码，再通过微信开发者工具编译、预览和调试。普通浏览器或 `npm start` 不能直接运行完整小程序。

```text
.

├── app.wxss                     # 全局样式
├── project.config.json          # 微信开发者工具项目配置
├── project.private.config.json  # 开发者本地工具配置
├── sitemap.json
├── components/
│   └── custom-tab-bar/          # 底部导航组件
├── pages/
│   ├── index/                   # 店铺首页、商品分类、加购
│   ├── detail/                  # 商品详情
│   ├── cart/                    # 购物车、配送方式、地址选择
│   ├── address/                 # 地址列表
│   ├── add-address/             # 新增和编辑地址
│   ├── order/                   # 下单确认、运费、付款弹窗
│   ├── orders/                  # 我的订单
│   ├── pay/                     # 继续付款
│   ├── admin-login/             # 当前本地管理登录入口
│   └── admin/
│       ├── admin.*              # 订单、商品、店铺和收款码管理
```

## 运行前准备

需要准备：

1. 微信开发者工具和用于登录工具的微信账号。
2. 小程序 AppID，以及该小程序的开发者权限；也可以使用自己有权限的测试小程序和对应云环境。
3. 可用的云开发环境，具有部署云函数、配置数据库和上传测试图片的权限。
4. 数据库集合、初始化配置文档，以及与业务匹配的数据库和云函数访问规则。

备份中的 AppID 和环境 ID 需要核对是否仍可访问。仅拥有源码不代表拥有原云环境权限。建议使用独立测试环境和虚构订单数据完成调试。

### 1 导入项目

在微信开发者工具中导入包含 `app.js` 和 `project.config.json` 的目录，填写自己有开发权限的 AppID，核对云函数根目录为 `cloudfunctions/`。

配置文件记录的基础库版本为 `3.15.1`。根据工具提供的可用版本进行兼容性核验，不将配置中的版本号视为已验证运行环境。

### 2 配置云环境

修改 `app.js` 的环境设置：

```js
wx.cloud.init({
  env: 'YOUR_TEST_ENV_ID',
  traceUser: true
});
```

云函数通过 `cloud.DYNAMIC_CURRENT_ENV` 使用部署所在环境。确认小程序选择的环境与四个云函数部署的环境一致。

### 3 部署云函数

在开发者工具的云开发功能中，将以下函数部署到测试环境，并安装各自的依赖：

```text
login
getproducts
createorder
getallorders
```

若工具支持“上传并部署：云端安装依赖”，可按此方式部署；具体菜单以安装版本为准。依赖安装、云函数部署和数据库配置是独立步骤，仅导入项目不会自动完成它们。

### 4 创建数据库集合

| 集合 | 用途 | 初始化方式 |
|---|---|---|
| `products` | 商品 | 手工加入测试商品，或在权限配置完成后通过后台新增 |
| `carts` | 购物车 | 创建空集合，顾客加购时写入 |
| `addresses` | 地址 | 创建空集合，新增地址时写入 |
| `orders` | 订单 | 创建空集合，由下单云函数写入 |
| `shop_config` | 店铺和轮播 | 创建 `_id` 为 `shop_info` 的文档 |
| `payment_config` | 收款码 | 创建 `_id` 为 `payment_code` 的文档 |

一条最小测试商品示例，数据库自动生成 `_id`：

```json
{
  "name": "测试司康",
  "price": 11.9,
  "desc": "用于开发环境的演示商品",
  "category": "冰乳酪司康",
  "isOnSale": true,
  "isFeatured": true,
  "monthSales": 0,
  "image": ""
}
```

分类需与当前源码中的名称一致：`冰乳酪司康`、`酥性饼干`、`养生膏体`。首页默认显示第一类。`image` 留空时首页使用图标占位，也可填写测试云存储文件 ID。

店铺配置示例：

```json
{
  "_id": "shop_info",
  "address": "测试店铺地址",
  "wechatList": ["测试联系账号", ""],
  "phoneList": ["", ""],
  "deliveryTimeList": ["测试环境，不实际发货", "", ""],
  "banners": []
}
```

收款码配置示例：

```json
{
  "_id": "payment_code",
  "imageUrl": ""
}
```

空 `imageUrl` 只用于验证配置读取；要预览图片，上传不用于真实收款的演示图片，并填入其云文件 ID。

### 5 核对访问规则与管理入口

数据库安全规则、云函数调用权限和索引均未随备份提供，需要向原开发者取得并核对。应分别定义商品/店铺公开读取、顾客本人数据和后台管理权限。

当前后台登录逻辑位于 `pages/admin-login/admin-login.js`，测试账号由其中的 `ADMIN_ACCOUNT` 和 `ADMIN_PASSWORD` 常量决定。该入口只在客户端比较账号口令并保存 `adminLogin` 标志，没有云端管理员身份认证。

管理页直接写商品、订单和店铺配置，因此仅修改登录页口令不能建立可靠的后台权限。接入新环境时需核验哪些操作会被现有规则拒绝，并将管理操作迁移至带角色检查的云函数；不要通过开放全部集合读写来替代这项工作。

### 6 配置订单通知

`cloudfunctions/createorder/index.js` 中的 `webhookUrl` 用于企业微信机器人通知。源码内置值需要核对；推荐改为读取云函数环境变量，并在未配置时跳过发送。仅在授权的测试群中验证，避免向原商家群发送测试订单。

当前通知为异步尝试，没有持久化重试任务，也没有严格检查业务返回码；下单成功不等于机器人通知一定送达。该配置改造属于待办，README 不代表源码已经实现环境变量读取。

### 7 编译和验证

完成环境配置后，编译并依次检查：

1. `login` 返回 OpenID，首页显示店铺信息与测试商品。
2. 加入购物车、调整数量，导航角标同步变化。
3. 新增测试地址，切换自取和配送，核对运费。
4. 创建测试订单，在顾客和后台两侧检查同一订单。
5. 提交付款确认，后台确认并标记完成。
6. 新建另一笔待支付订单并取消，检查状态展示。
7. 在具备正确权限的测试身份下验证商品和店铺编辑。

如果编译报自定义导航路径或 WXML 表达式错误，优先检查 `app.json` 的 `tabBar.custom`、`components/custom-tab-bar/` 的引用方式，以及模板中的方法调用表达式。当前备份尚未通过开发者工具编译验收，可能需要先做兼容性修复。

## 现有业务规则

### 运费

当前规则在 `pages/order/order.js` 的 `calcShippingFee()` 中：

| 方式或地区 | 运费 |
|---|---|
| 自取 | 0 元 |
| 黑龙江、吉林、辽宁、内蒙古、河北、北京、天津、山西 | 商品金额低于 88 元收 10 元，否则免运费 |
| 其他省份 | 商品金额低于 108 元收 13 元，否则免运费 |

这些规则目前由客户端计算，云函数没有重新校验。

### 订单与付款

```text
创建订单 → 待支付
顾客点击付款确认 → 待确认
后台确认 → 已确认
后台再次更新 → 已完成

待支付订单 → 顾客取消 → 已取消
```

部分页面兼容旧状态 `待处理`；后台也允许从待支付直接确认。上述为当前实现，不代表已建立完整的云端状态机。

付款采用收款码展示和人工确认，未实现微信支付 API、支付回调或收款结果核验。页面上的“支付成功”文字不能作为实际收款证据。

## 已知限制与后续开发

当前备份需要重点完善：

- 云端三角色授权、订单归属检查和管理操作权限。
- 服务端商品有效性、数量、现价和运费校验，金额采用明确的精度规则。
- 库存预留与释放、数据库事务、重复提交保护和订单状态机。
- 月销量与收入统计口径，避免将待支付、已取消订单计作有效销售。
- 支付或人工核验流程、售后与退款、发货/自取记录。
- 分页、索引、默认地址唯一性和购物车并发更新。
- 结构化操作日志、通知结果与重试、自动化测试和部署文档。

离线代码检查已发现：创建订单函数接受客户端声明的总价；重复提交创建多笔订单；商品更新失败后订单仍可能已写入；空商品列表可创建订单。查询全部订单函数体未执行角色检查。真实环境是否另有调用限制，需要核对控制台配置。

以上依据当前备份的源码与模拟数据库检查，不是线上系统测试结果。

## 常见问题

| 现象 | 检查方向 |
|---|---|
| 获取 OpenID 失败 | AppID、开发者权限、云环境、`login` 部署和调用权限 |
| 首页没有商品 | `products` 数据、上架状态、分类名称、`getproducts` 部署与查询结果 |
| 云数据库操作被拒绝 | 集合安全规则、调用身份及记录归属；后台还需核验服务端授权 |
| 店铺信息为空 | `shop_config/shop_info` 是否存在，字段和读取权限是否匹配 |
| 收款码不显示 | `payment_config/payment_code`、`imageUrl` 和云文件访问权限 |
| 页面提示“请稍后重试” | OpenID 异步获取是否完成，控制台是否有登录调用错误 |
| 后台统计与订单数不一致 | 查询是否完整、统计是否包含取消/待支付订单以及时间格式 |
| 下单成功但通知未到 | webhook 配置、云函数日志、外部请求与机器人业务返回码 |
