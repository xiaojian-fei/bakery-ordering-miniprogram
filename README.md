# 烘焙商品预订与订单管理系统（网页端）

软件工程期末综合实践项目。面向单家烘焙门店的**商品预订与订单管理 Web 系统**：顾客在线下单，
店员履约，店主管理与对账。浏览器直接访问，运行时不需要微信开发者工具、微信账号或云开发。

> 本项目最初是原生微信小程序（`bakery-ordering-miniprogram`），现已迁移为独立 Web 系统：
> 后端换成 Node.js 单体服务 + SQLite 文件数据库，前端换成浏览器原生 ES 模块页面，
> 小程序专有代码已删除。迁移背景与阶段划分见 [`docs/Web重构方案.md`](docs/Web重构方案.md)，
> 运行与验收见 [`docs/网页端运行与验收.md`](docs/网页端运行与验收.md)，数据库设计见
> [`docs/数据库设计.md`](docs/数据库设计.md)，上线部署见 [`docs/部署与运维.md`](docs/部署与运维.md)，
> 架构与失败恢复见 [`docs/网页端架构与业务模型.md`](docs/网页端架构与业务模型.md)、
> [`docs/失败恢复机制.md`](docs/失败恢复机制.md)。

## 快速开始

```bash
# 需要 Node.js ≥ 24（使用内置 node:sqlite，无需安装数据库）
npm start                 # 启动后访问 http://127.0.0.1:8080
```

首次启动自动建库、建表、写入演示商品，并创建首个店主账号；口令随机生成且**只在本次启动打印**。
也可以自己指定：

```bash
OWNER_USERNAME=owner OWNER_PASSWORD='你的强口令123' npm start
```

| 角色 | 账号来源 |
|---|---|
| 顾客 | 页面自助注册（口令至少 8 位） |
| 店员 | 店主在「店铺管理 → 员工账号」创建（口令至少 12 位） |
| 店主 | 首次启动初始化 |

## 功能

**顾客**：按分类浏览与搜索商品 → 加入购物车 → 维护收货地址 → 选配送或自取、确认报价（含运费）
→ 提交订单 → 模拟支付 / 取消 → 查看订单进度与自取核销码 → 申请售后。

**店员**：履约工作台按状态推进订单 —— 接单、发货（承运方与运单号）、备货完成、
自取核销码校验完成。

**店主**：商品上下架与图片上传、库存调整（带原因与审计）、店铺信息与运费规则、售后审核、
整单退款、经营统计（收款 / 退款 / 净额 / 销量）、员工账号创建与启停。

## 技术栈

| 部分 | 选择 | 说明 |
|---|---|---|
| 前端 | 浏览器原生 ES 模块 + CSS | 零构建、零依赖，`shared/` 里的客户端 SDK 与 Node 端共用同一份代码 |
| 后端 | Node.js 内置 `node:http` 单体服务 | 静态资源、业务接口、上传同源提供 |
| 数据库 | SQLite（`node:sqlite`） | 单文件、WAL、真实事务；每个集合一张具名表 |
| 身份 | 用户名 + scrypt 口令 + HttpOnly 会话 Cookie | 员工令牌也只走 Cookie，页面脚本拿不到原文 |
| 测试 | `node:test` | 267 项，可整体切换真实数据库运行 |

没有第三方运行时依赖，`package.json` 中没有 `dependencies`。

## 项目结构

```
core/                业务核心（与平台无关，38 个业务动作）
  application.js       统一入口：动作路由 + 可信身份解析
  domain/              计价、库存、订单状态机、履约、售后、退款、统计、权限、审计…
  jobs/                超时关单、通知投递（outbox）
  setup/               首个店主初始化
shared/              浏览器与 Node 共用的交易客户端
  trade-client.js      客户端 SDK（只依赖注入的 send）
  checkout-attempt.js  一次人工确认的结算意图，重试不重复下单
  *-recovery.js        失败后恢复：结算、履约、售后（已接入页面，存储由调用方注入）
server/              网页端运行时
  index.js http.js accounts.js sessions.js config.js bundle.js db/
web/                 前端页面（原生 ES 模块）
  index.html app.js ui.js styles.css views/
test/                自动测试（领域 / 仓储 / HTTP）
scripts/             run-tests、smoke-web、ui-check、demo-*
docs/                方案、架构、数据库、运行与验收文档
```

## 架构要点

1. **业务核心与平台解耦**：`core/` 只认 `repository.transaction()` 与注入的 `resolveIdentity`，
   不知道 HTTP、Cookie 或微信的存在。迁移时这层一行没改，靠的是原来就有的接口隔离。
2. **传输层只做身份翻译**：`server/http.js` 把 Cookie 解析成可信 `openid` 与员工令牌，
   交给 `application.handle()`；请求体里的身份字段一律不采信。
3. **同一份客户端**：浏览器通过 `/api/client.js` 拿到由 `shared/` 现场生成的 SDK，
   与 Node 测试、冒烟脚本用的是同一份交易客户端，页面不另写一套请求逻辑。
4. **真实事务**：`BEGIN IMMEDIATE` + 串行队列 + 回滚；库存竞争、重复下单、重复退款都由
   领域层的不变量与数据库事务共同保证。

## 验证

```bash
npm test              # 267 项：领域 + 仓储 + HTTP + 恢复协议（内存夹具）
npm run test:sqlite   # 267 项：同一批断言跑在真实 SQLite 上
npm run smoke         # 28 项端到端：注册→下单→支付→履约→售后→退款→统计→上传
npm run smoke:verify  # 6 项：重启服务后订单、金额、事件流水仍在
npm run ui            # 31 项无头浏览器验收（真实下单、支付、找回草稿、店员接单）
npm run load          # 50 并发抢 10 件库存 + 500 并发查询，验零超卖与延迟
```

当前实测（Node 24.21 / SQLite 3.46.1 / 无头 Chromium）：

| 项目 | 结果 |
|---|---|
| 自动测试（内存夹具 / 真实 SQLite） | **267 / 267**（两种仓储各一遍） |
| 端到端业务冒烟 | **28 / 28** |
| 停服重启后持久化 | **6 / 6** |
| 无头浏览器验收 | **31 / 31**，零前端异常 |
| 50 并发抢 10 件库存 | 恰好 10 单成功、40 单 `OUT_OF_STOCK`，**零超卖** |
| 500 并发查询 | p50 7.2 ms、p95 11.4 ms、max 13.8 ms，约 1990 请求/秒 |
